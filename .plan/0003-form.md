### 2.2 `registry.rs` — desenho sugerido

```rust
pub struct FormChildId(u64);                    // Copy, Eq, Hash, Debug

pub struct ChildEntry {
    pub id: FormChildId,
    pub name: Option<String>,                   // para eventos/diagnóstico
    pub validate: Rc<dyn Fn() -> LocalBoxFuture<'static, Result<bool, String>>>,
    pub reset_validation: Option<Rc<dyn Fn()>>,
    pub focus: Option<Rc<dyn Fn() -> bool>>,    // true = conseguiu focar (montado/ativo)
}

pub struct Registry { next_id: u64, entries: Vec<ChildEntry>, validate_index: u64 }

impl Registry {
    pub fn bind(&mut self, …) -> FormChildId;
    pub fn unbind(&mut self, id: FormChildId);
    pub fn reset_validation(&mut self);          // incrementa validate_index + chama reset de todos
}

pub enum ValidationOutcome {
    Valid,
    Invalid { failed: Vec<FormChildId> },        // na ordem de registro
    Superseded,                                  // uma validação mais nova começou: não emitir nada
}

/// Recebe um *snapshot* dos filhos (clonar os Rc antes de await — o registro pode mudar durante a validação).
pub async fn run_validation(children: Vec<ChildEntry>, greedy: bool) -> Result<(), Vec<(FormChildId, Option<String>)>>;
```

- `Err(msg)` de um filho = inválido; o `msg` é logado (`console.error` no componente). Equivale ao "rule que lança" do Quasar — **não usar panic** como sinal.
- Não-greedy: sequencial, para no primeiro inválido. Greedy: `futures::future::join_all`.
- O controle de "superada" usa `validate_index` capturado antes do `await` e comparado depois — fica no lado que segura o `Registry` (o componente), mas a regra deve ser testável: exponha um helper puro (ex.: `ValidationTicket`) ou teste via o `FormHandle` com um registro injetado.
- Foco no erro: primeiro filho inválido cujo `focus()` retorne `true` ("skips failing components that cannot receive focus").

### 2.3 Testes (`cargo test`, host) — portar de `~/repos/quasar/ui/src/components/form/QForm.test.js`

Usar `futures::executor::block_on` / `LocalPool` e `futures::channel::oneshot` para controlar quando cada validação resolve.

| Caso do Quasar | Teste |
|---|---|
| `validates async fields one at a time when not greedy` | o 2º `validate` só é chamado depois que o 1º resolve |
| `validates async fields concurrently when greedy` | todos chamados antes de qualquer um resolver |
| `(prop)greedy type Boolean has effect` | não-greedy para no 1º inválido; greedy coleta todos |
| `a superseded validation emits no events` | validação A em voo, B começa → A resulta `Superseded` |
| `drops a submission superseded while validating` | submit em voo + nova validação → submit não ocorre |
| `focuses the first failing component by default` / `skips failing components that cannot receive focus` | escolha do alvo de foco |
| `(prop)no-error-focus` + `an explicit validate(true) overrides it` | regra de `should_focus` |
| `unregisters removed fields from validation` | `unbind` tira o filho do próximo `validate` |
| `lets the reset listener run before validations are reset` | ordem `on_reset` → `reset_validation` |
| validação que falha com `Err` | conta como inválida, não derruba |

### Critério de aceite 2
Todos os casos acima como testes verdes em `cargo test -p <nome>-ui`, sem dependência de DOM.

## 3. `Form` — componente Leptos + `use_form_child`

### 3.1 Contexto e `!Send`

- O `Registry` vive em `StoredValue::new_local(…)` (closures e futures são `!Send`; `provide_context` exige `Send + Sync`). O contexto fornecido é um struct `Copy` com esse `StoredValue` — ver `docs/guide/pitfalls.md`.

### 3.2 `<Form>`

Props (ver tabela em `docs/ui/forms.md#api-proposta`): `autofocus`, `no_error_focus`, `no_reset_focus`, `greedy`, `on_submit: Option<Callback<SubmitEvent>>`, `on_reset: Option<Callback<()>>`, `on_validation_success: Option<Callback<()>>`, `on_validation_error: Option<Callback<FormChildId>>`, `handle: Option<FormHandle>`, `children`. Atributos extras (`action`, `method`, `autocomplete`…) repassados ao `<form>` (`attr:` do Leptos).

- `on:submit` → `prevent_default` → `submit()`; sem `on_submit`, após validar chama `HtmlFormElement::submit()` (envio nativo).
- `on:reset` → `prevent_default` → `on_reset` → no próximo tick (`request_animation_frame`/`queue_microtask`) `reset_validation()` e, se `autofocus && !no_reset_focus`, `focus()`.
- `autofocus` → `focus()` após montar (`Effect`/`request_animation_frame`).
- Classe do `<form>`: um shortcut literal (ex.: `form`) — CSS mínimo (`position: relative`); o pipeline de CSS do crate é do plano seguinte (ADR-0005).

### 3.3 `FormHandle` (`Copy`)

`FormHandle::new()` → passado em `handle=`; o `<Form>` o conecta ao seu registro. Métodos: `validate(should_focus: Option<bool>) -> impl Future<Output = bool>`, `reset_validation()`, `submit()`, `reset()`, `focus()`, `children() -> Vec<FormChildId>`. Chamar antes do `<Form>` montar → no-op/`false` (documentar).

### 3.4 `use_form_child`

```rust
pub struct FormChildOptions {
    pub name: Option<String>,
    pub validate: Rc<dyn Fn() -> LocalBoxFuture<'static, Result<bool, String>>>,
    pub reset_validation: Option<Rc<dyn Fn()>>,
    pub focus: Option<Rc<dyn Fn() -> bool>>,
    pub disabled: Signal<bool>,
    pub requires_form: bool,
}
pub fn use_form_child(opts: FormChildOptions) -> Option<FormChildId>;
```

Comportamento (porta de `use-form-child.js` e do teste `binds to QForm, reacts to disable, unbinds, and reports missing QForm`):
- sem `Form` acima: nada; com `requires_form`, `leptos::logging::error!`;
- registra se não `disabled`; `Effect` sobre `disabled`: `true` → `reset_validation` + `unbind`; `false` → `bind`;
- `on_cleanup` → `unbind`.

Ajuste a assinatura se o Leptos pedir (ex.: `Rc` vs `Arc`, `Callback`), mantendo o contrato.
